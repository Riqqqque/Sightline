# Decisions

Settled 2026-11-23, after Phase 0. Each one is a default that can be revisited; the ones marked
"setting" can be changed at runtime without a rebuild.

| # | Question | Decision | Why |
| --- | --- | --- | --- |
| 1 | Data path | **A**: local client for the live roster, HenrikDev for stats. "Look up other players" is a setting, default on. Off gives path C. | Keeps the heavy lookups off the Riot session and inside a revocable key. One build covers both A and C. |
| 2 | Names | One name-service call per lobby through the client session, non-hidden players only. | One request instead of 10 to 20 rate-limit units, so ranks are not delayed. |
| 3 | Win estimate | Kept, labelled as an estimate. Setting: on, bar only, off. Default on. | It is in the spec. The toggle is there because it sits near Riot's wording on rating calculators. |
| 4 | Smurf flag | Kept. Setting, default on. Tuned to stay quiet. | Same reasoning. |
| 5 | Agent select | Shows my team. Enemy slots stay empty until the match loads, if the live check confirms enemies are not available earlier. | Nothing to choose; the layout is fixed so it does not jump. |
| 6 | Hidden players | Agent and a "Hidden" badge only. No name, no lookups, no party bracket, nothing stored, also dropped from post-game data. | Hard rule. |
| 7 | My party members who hide their names | Shown. | The game already shows them to me. |
| 8 | An identity flag missing from Riot's data | Treated as hidden. | Fails safe if Riot renames a field. |
| 9 | Window width | Capped at 1280 logical px. | Memory is 4 bytes per pixel; the cap keeps the app near 30 MB at any size. |
| 10 | The 40 MB target | Measured as Private Bytes. Working Set is reported next to it. | Working Set includes about 15 MB of shared system pages no app controls. |
| 11 | Raw match JSON | Not kept. | 100 to 300 KB per match, and it would retain the names of hidden players. |
| 12 | Font | Segoe UI Variable for now: it ships with Windows 11 and costs no memory or download. Inter (SIL OFL 1.1) stays the candidate for the one bundled font in step 3. | The spec asks for one bundled font; bundling needs a download, so it waits until Rique says yes to the file. |
| 13 | Request headers to Riot | Only the headers the endpoints require, plus a plain generic user agent. No game user-agent string. | The fork imitates the game client's user agent; Sightline does not pretend to be the game. |
| 14 | Agent select refresh | Every 5 s until all five agents are locked, then stop. One request per refresh. | Picks change during agent select; nothing changes after lock. |
| 15 | When Riot refuses a request | No retry on a refusal or an unreadable answer. 429 and 5xx: 15, 30, 60 s, then stop. | Repeating a refused request is the opposite of low-profile. |
| 16 | Name lookups | Each player is asked about once per lobby. Any answer is final, also a refusal or a 429. Only a lookup with no answer at all is repeated, twice at most. | Found in review: a failed lookup was being sent again on every 5 s refresh. |
| 17 | Agent and map names | Fetched once and kept. While the fetch fails: two tries per lobby, then wait for the next lobby. | Found in review: a failing fetch was being repeated on every refresh. Per lobby, so one network blip does not cost the names for the whole session. |
| 18 | App icon | Option B, "Two rosters": two columns of bars, mine and theirs. The other three stay in `assets/icon/options/`. | Rique chose it 2026-11-24. |
| 19 | Recent matches of other players | The "stored matches" endpoint, last ten ranked matches, one line per match for the looked-up player only. | Same cost as any other call, and it never returns the other nine players. |
| 20 | Cost per stats call | Assumed 2 units, 2 always left unspent: at most 14 calls a minute. | Measured 2026-11-24: every call took 2 of the 30, cached or not. |
| 21 | Lookup order | One at a time: me, my team, the other team; all ranks before any history. | Simple, cannot burst past the limit, and the most useful numbers arrive first. |
| 22 | Result of my match | Fetched 45 s after it ends, then twice more 310 s apart, then not again. | The service keeps an answer for five minutes; asking sooner returns the same one. |
| 23 | Smurf flag rule | Needs a new-looking account and strong recent results together (`docs/smurf-score.md`). | Strong results alone would flag every good player. |
| 24 | Win estimate | A logistic curve on the average rank difference; needs three known ranks per side; clamped to 5 to 95%. | Honest about being rough. "bar" hides the number. |
| 25 | Seen before, when switched off | No new meetings are recorded, and none are shown. Players are still listed in the database with their last rank, because the cards need that. | Off should mean off, not "hidden but still collecting". |
| 26 | Player details | Open on click, in a panel above the footer. | A click also gives the note field a place to live. |
| 27 | Images and bundled font | Superseded by 33 and 34. | Rique approved the art download on 2026-11-24. |
| 28 | Database layout | Simpler than the Phase 0 proposal: text names, small indexed queries, no running-total tables. Layout at the top of `src/store.rs`. | Ten matches per player makes totals tables unnecessary. |
| 29 | Stat lookups for my party members who hide their names | Looked up, like any visible player. **Open to overrule:** the spec says "Incognito: no stat lookups"; read strictly, they would be shown by name but get no rank or history. | Follows decision 7: the game already shows them to me, so nothing hidden is revealed. Not yet confirmed by Rique. |
| 30 | Order within a column | Me, then players that can be shown, then hidden players. | Rique asked for it 2026-11-24: the rows with something to read come first. |
| 31 | Deathmatch | Shown live with stats. Not stored as a match of mine, not in the session, players not "seen before". | No teams and no result, so "with", "against", win and loss mean nothing there. |
| 32 | A match without teams | One list, "PLAYERS", spread over both columns. | The game gives everyone the same team id in deathmatch; found live. |
| 33 | Look | "Scoreboard": VALORANT's own scoreboard as the model. Team-tinted bars, agent face, rank badge, capitals, W and L letters for the last five. Chosen by Rique from three mockups. | The first, flat design was rejected as plain, not VALORANT enough and hard to read. |
| 34 | Art | Agent faces, rank badges, agent portraits and map banners from media.valorant-api.com, shrunk to display size and built into the exe. Originals stay in `assets/art/src`, never committed. | Approved by Rique (42 MB offered, 38 MB fetched). Built in, so nothing is downloaded while the app runs. |
| 35 | Font | Bahnschrift, already on Windows. Inter is dropped. | Same DIN shapes as the game's own font, and no download. |
| 36 | Who the side panel shows unasked | The opponent with the best recent KD; in a match without teams, the best of everyone else; in agent select, me. Never a hidden player. | It answers "who do I watch" without a click. |
| 37 | Hidden players, after the match | **Changed by Rique on 2026-11-24.** Once a match of mine is over, its scoreboard lists all ten players by name with that match's numbers, as the game's own end screen does, including those who hid their name while it was live. They are kept from that one match (their line, their name, that we met). Nothing is ever looked up about them, and in any later lobby where they hide again they are hidden again. This replaces the post-game half of decision 6. | The game itself names them once the match ends. With half of a ranked lobby hidden (5 of 10 seen live), dropping them after the match too left the recap and "seen before" nearly empty. |
| 38 | Hidden players, during the match | Unchanged and not negotiable in code: no id is kept for a hidden slot, so no name, rank, history, note or "seen before" can be shown for it. | Riot's and HenrikDev's wording is about exactly this: revealing someone who is hidden right now. |
| 39 | Live numbers during a match | Only the round score, which the Riot Client reports about my own match. Per-player kills and deaths during a match are not available without reading the game's memory or the screen, and are not attempted. | Read-only rule; Vanguard. They arrive with the scoreboard about a minute after the match. |
| 40 | My full history | Everything the stats service has stored of my ranked matches, a hundred per request, once a day while idle. Not tracker.gg: it has no public VALORANT interface and blocks automated reading. | Same data, through the key already in use, for a handful of requests. |
| 41 | Shooting range | Treated as the menus. | The client reports it as "in game"; it was being recorded as a match (found live). |
| 42 | Publishing | **Changed by Rique on 2026-11-24:** public repository `Riqqqque/Sightline`, MIT licence, releases for other people. This replaces "personal use only, never publish" from the original spec. | Rique wants others to be able to use it. The README says plainly that Riot lists this kind of tool as unapproved. |
| 43 | Artwork in a public project | Not in the repository. The released exe contains display-size copies; `tools\make-art.ps1` fetches the originals for anyone building it. A checkout without art still builds, with letters and text. | Riot's fan-project policy allows free, non-commercial use; keeping the files out of the repository keeps the licence clean. |
| 44 | Updates | Once a day, and never during a match, the app asks GitHub for the newest release. Installing is a click in Settings: download, SHA-256 check against the published checksum, swap, restart. Only this repository's release addresses over HTTPS are accepted. Can be switched off. | Other people need a way to stay current; a silent self-updater would be the wrong thing for a tool that asks for trust. This replaces "no update checks" from Phase 0. |
| 45 | Names after the match, for everyone else | A setting, **off for a new install**: players who were hidden stay nameless on the scoreboard (numbers and agent only) and nothing about them is kept. One click turns it on. An install that already has finished matches from before the setting existed keeps the earlier behaviour (on), which is what decision 37 chose. | HenrikDev's terms name showing hidden names as not allowed, and a public build runs on every user's own key: the careful default belongs to the public, the choice to each user. |
| 47 | Paths inside the exe | Builds remap the user profile and the repository folder to `~` and `.` (`tools\quiet-cargo.ps1`, `tools\release.ps1`), and the release script refuses to publish an exe that contains the Windows account name. | A release build otherwise carries the builder's account name in hundreds of file paths (found before the first upload). |
| 46 | SHA-256 | Windows' own implementation (`BCryptHash`), through `windows-sys`. | No new crate to carry or to trust for one hash. |
